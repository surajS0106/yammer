# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

The repo has a Bun workspace (`apps/*`) and a Cargo workspace (`crates/voice-core`, `apps/desktop/src-tauri`).

```sh
bun install
bun run dev                  # tauri dev; Vite on fixed port 1430 (Sush uses 1420, so both can run)
bun run typecheck            # tsc
bun --filter desktop build   # tsc + vite build; also needed before `cargo test` on a clean checkout (generate_context! wants dist/)
bun run build                # release installers for this platform
bun run build:mac            # macOS DMG only (sets MACOSX_DEPLOYMENT_TARGET=11.0 for whisper.cpp); see /build-dmg
bun run build:android        # debug APK for phones and x86_64 emulators; needs JAVA_HOME, ANDROID_HOME and NDK_HOME

cargo test --workspace
cargo test -p voice-core <name_substring>
# Real whisper inference (model + 16 kHz mono WAV):
WHISPER_MODEL=... WHISPER_WAV=... cargo test -p yammer transcribes_real_audio -- --ignored --nocapture
cargo fmt --all               # rustfmt.toml sets the house style; CI runs --check
cargo clippy -p yammer --all-targets
# What CI runs for voice-core (no whisper.cpp, so deps don't need opt-level 3):
cargo clippy -p voice-core --all-targets --config 'profile.dev.package."*".opt-level=0' -- -D warnings
cargo test -p voice-core --config 'profile.dev.package."*".opt-level=0'
```

There are no JS tests and no JS linter; `typecheck` is the TypeScript gate. Building whisper.cpp needs CMake and libclang. On Windows, set `CMAKE` and `LIBCLANG_PATH` if they aren't on PATH. Dev builds compile dependencies at `opt-level = 3`, because whisper is unusably slow without it.

CI (`.github/workflows/ci.yml`) has a 3-minute budget. It runs typecheck, the frontend build, `cargo fmt --check`, and voice-core clippy and tests on Linux. It never builds the `yammer` crate, so run `cargo test --workspace` locally. Releases are manual. Start `release.yml` from the Actions tab or with `gh workflow run release.yml`. It builds every platform and tags the release `v<version>` from `apps/desktop/src-tauri/tauri.conf.json`. Pushing a tag doesn't trigger it. Its release notes are that version's section of the user-facing `CHANGELOG.md`, and it stops if there isn't one: add user-visible changes to `## Unreleased` as you make them, and rename it to `## <version> — <YYYY-MM-DD>` when bumping the version.

Rust formatting is enforced. `rustfmt.toml` matches the code's dense style (`max_width = 150`, `use_small_heuristics = "Max"`), so run `cargo fmt --all` after Rust edits. Clippy must be warning-free, and CI runs it with `-D warnings` on voice-core. macOS-only code (`dock.rs`, `panel.rs` and the `cfg(target_os = "macos")` arms) only compiles and lints on a Mac. Project skills: `/typecheck` (fast), `/check` (the pre-push gate that mirrors CI), `/ship` (check, commit, push), `/build-dmg` (a local ad-hoc signed macOS DMG), and for Android `/build-apk`, `/android-check` (CI and `/check` never compile Android code), `/android-test` (drive an emulator) and `/android-release` (before anyone else gets a build).

## Architecture

Yammer (formerly Larp), a product of Sush: a dictation app modelled on Sush (`../sush`), whose whisper, transcription, secrets and error code it adapts.

- **`crates/voice-core`** is pure Rust with no Tauri dependency, and it should stay that way. It holds:
  - `audio.rs`: downmix, resample to 16 kHz, silence detection, WAV encode and decode.
  - `models.rs`: the whisper model catalog, each entry pinned by size and SHA-256.
  - `settings.rs`: `settings.json`. Every field has a serde default, so old files load. Struct fields serialize as camelCase and enums as kebab-case, and `lib/tauri.ts` must use the same casing.
  - `history.rs`: `history.json`, plus `recordings/<id>.wav` for the newest `keepRecordings` entries, so a dictation can be transcribed again. Failed dictations are saved too (`error`, empty `text`) so they can be retried. `prune` applies `historyDays`.
  - `scratchpad.rs`: the Scratchpad's notes as `scratchpad.json`. Older builds kept them in localStorage; `pages/scratchpad.tsx` moves them over.
  - `meetings.rs`: meeting transcripts, one `meetings/<id>.json` each (so saving mid-call doesn't rewrite the rest): segments tagged `You` (mic), `Them` (system audio) or `Room` (a phone's mic, hearing everyone), the user's own notes, and the written-up notes.
  - `live.rs`: live transcription without a socket. `Segmenter` cuts 16 kHz audio into turns at pauses (OpenAI's `gpt-live-transcribe` has no server VAD, so the app commits each turn), plus the OpenAI Realtime and Sarvam streaming messages.
  - `transcribe.rs`: cloud speech-to-text over `/audio/transcriptions` or Ollama chat.
  - `cleanup.rs`: the LLM cleanup prompt and request for OpenAI chat or Anthropic messages, plus `rewrite` (Scratchpad transforms), `edit` (edit by voice) and `summarize` (meeting notes, starting with a `# Title` line that `meetings::split_title` takes off).
- **`apps/desktop/src-tauri`** (crate `yammer`) is the OS shell.
  - `dictation.rs` is the heart of the app. A single task consumes `Input`s (hotkey Down/Up, Toggle, Cancel, Cap, NoSelection, Retry, Finished) in order:
    - **Modes:** each hotkey starts a `Mode`: `Dictate` (the active transform), `Transform(id)` (a transform's own hotkey, which runs cleanup even when it's off), or `Edit` (copies the selection with Ctrl/⌘+C as recording starts, then rewrites it as the speech asks).
    - **Hold vs. tap:** a release within 300 ms latches into toggle mode.
    - **Pipeline:** stop recording → resample → whisper or cloud → optional cleanup (falls back to the raw text) → paste → history, with the audio. A failure is saved as an entry, and the overlay's failed card offers Retry (`Input::Retry`, which pastes); History's "Transcribe again" (`dictation::retry`) only updates the entry and emits `history-updated`.
  - `meeting.rs`: meeting transcripts, separate from dictation. Each channel (mic, and system audio from `recorder::live`) gets its own task: it streams turns over a WebSocket (`tokio-tungstenite`) to OpenAI Realtime or Sarvam, reconnecting if dropped and otherwise falling back to the dictation engine, or transcribes each turn with `pipeline::transcribe`. Saved every 5 s and on exit; on stop, the AI cleanup model writes the notes (`summarize`). While one runs, the overlay's idle state is `Meeting` and dictation doesn't mute the output. The streaming engine uses its provider's key, the same one the speech engine or cleanup would use. Shared with Android, where `channels` and `open` are one `Room` channel from `android::meeting_audio`; `tokio-tungstenite` uses rustls there, as reqwest does.
  - `hotkey.rs`: registers every hotkey in the settings (`bindings`: dictation, edit, per-transform, meeting) and rejects duplicates. A binding's `Action` is a dictation `Mode` or `Meeting`. The `tauri-plugin-global-shortcut` handler only forwards events. Registering a shortcut blocks on the main thread, so never do real work in the handler. Esc is registered only while recording.
  - `recorder.rs`: cpal capture on its own thread, because the stream isn't `Send`. `live` hands over 16 kHz audio every 50 ms for meetings, from the mic or the system output: cpal loopback on macOS 14.6+ (needs `NSAudioCaptureUsageDescription`, in both plists) and Windows, `parec` on the default monitor on Linux.
  - `paste.rs`: arboard clipboard plus an enigo Ctrl/⌘+V, then restores the clipboard. On Wayland it tries `wtype`, then on GNOME the RemoteDesktop portal (`portal.rs`), then `ydotool`, and otherwise the text is copied only.
  - `portal.rs` (Linux): a RemoteDesktop portal keyboard session, opened at startup on GNOME so its one-time permission dialog doesn't steal focus mid-paste. Its restore token is saved as `remote-desktop-token` in the config dir.
  - `gnome.rs`: on GNOME Wayland each hotkey is a GNOME custom shortcut (written with `gsettings`) that runs `yammer --toggle`, `--edit` or `--transform=<id>`. GNOME reports only the press, so it's tap-to-toggle. Esc is bound to `yammer --cancel` only while recording.
  - `focus.rs`: macOS Accessibility check for whether a text box has focus. Only a definite "no" skips the paste; the overlay then shows the transcript in a card with Copy (`Transcript` state). Unknown, Windows and Linux paste as before.
  - `overlay.rs`: a transparent, non-focusable, click-through pill window. It must never take focus, or the paste lands in the wrong app. On macOS, `panel.rs` turns it into a non-activating `NSPanel`, which lets it appear over other apps' full-screen Spaces. On Linux, the window's input shape is the hit areas (Sushi, the pill, the menu), rather than being toggled by the cursor poll.
  - `whisper.rs`: model download with SHA check, a cached context, and inference.
  - `tray.rs`: the menu has Transform, Language and Speech engine submenus. `tray::refresh` rebuilds it, and `commands::apply` (every settings change from Settings or the tray) calls it.
  - `mute.rs`: "Mute other audio" mutes the default output while recording (Core Audio COM on Windows, `osascript` on macOS, `wpctl`/`pactl` on Linux), and only undoes a mute it made.
  - `secrets.rs`: the OS keyring for API keys, one per provider (`KEY_NAMES` in `settings.rs`; custom servers get one per feature), so a key saved on any page serves every feature on that provider. `secrets::stt`/`cleanup`/`live` look up a feature's key; `migrate` moves the old per-feature `stt`/`cleanup`/`live` keys over at startup. Desktop debug builds use `dev-secrets.json` instead; Android uses `secrets.bin`, encrypted (below).
  - `commands.rs`. `error.rs`'s `AppError` serializes as a plain message string, so the UI shows it directly (`errorMessage` in `lib/tauri.ts`).
  - `state.rs`: `AppState` holds the settings and history behind mutexes, the models directory and a shared `reqwest` client.
  - `sounds.rs`: synthesized start, stop and error cues, played through cpal on a throwaway thread.
  - **Instances and windows:**
    - Single-instance: `yammer --toggle` from a second launch toggles dictation, which is the Wayland path.
    - Closing the main window hides it, and the app keeps running in the tray.
    - `--hidden` (used by autostart) skips showing the window once the user is onboarded.
- **Android** (`src-tauri/src/android/`, `src-tauri/gen/android`): the same crate and UI, without the desktop modules (`#[cfg(desktop)]` in `lib.rs`). `pipeline.rs` (speech to text, cleanup, history) is shared; `dictation.rs` is desktop's state machine. Cloud engines only, as whisper isn't built for Android.
  - Kotlin in `gen/android/app/src/main/java/com/sush/yammer` owns dictation: `YammerService` (a `microphone` foreground service, holding the state), `Bubble` (Sushi, a non-focusable overlay window), `Recorder` (`AudioRecord`, not cpal) and `YammerAccessibility` (pastes with `ACTION_PASTE`; without it the text is only copied).
  - Meetings: Android can't capture another app's call audio, so a meeting is the mic only. The Meetings page's `meeting_start` reaches the plugin's `startMeeting`, which starts the service without Sushi if it's off (`YammerService.forMeeting`, `onlyForMeeting`). `LiveRecorder` hands each 100 ms to `YammerNative.meetingAudio`, which returns false once Rust has stopped the meeting; the notification's Stop calls `meetingStop`. Dictation is refused while one runs. While listening (dictating or a meeting), the notification is an Android 16 live update redrawn every 300 ms (`Island.kt`): the small icon is a Sushi silhouette that blinks now and then, and `shortCriticalText` is an equaliser of Braille-dot bars that rise and fall in place (scrolling bars, a hopping Sushi and block characters looked jerky at that frame rate), which OnePlus's island and Pixel's status chip show. OxygenOS 16 shows a third-party live update only after the user turns the app on in Settings → Notifications & status bar → Live Alerts; it's off by default. Android caps an app at five notification updates a second. Meetings opens from a tile on Home, and its settings from the Meetings page rather than a fourth settings tab.
  - The service calls Rust over JNI (`YammerNative.kt`), since it outlives the activity. `YammerPlugin.kt` is only for the settings UI (`android_status`, `android_action`, `components/android-panel.tsx`). The UI branches on `isAndroid` in `lib/utils.ts`.
  - **Phone layout:** `components/bottom-nav.tsx` replaces the sidebar and title bar with a floating glass dock over the page, hidden while the keyboard is up: a pill of four tabs (72×48, never under 44 wide) and a round button beside it. That button dictates unless the page sets `useDockAction` (`lib/dock.tsx`), usually to "+". Teach groups Dictionary, Snippets and Transforms under sub-tabs; Insights and Settings open from Home's header, Help from Settings. Pages are bento grids on `isAndroid` (`PhoneHome` in `pages/home.tsx`, `NigiriCard`'s tiles, `GeneralPage`). Dropdowns and menus are bottom sheets (`Sheet` in `ui.tsx`, which `Select` uses); `useLongPress` opens History's. `ui.tsx` primitives size up for touch, and `index.css` steps text sizes up under `html[data-android]`. Export goes through Android's share sheet (`android_share`, `YammerPlugin.shareFile`). `lib/theme.ts` calls the `barsLight`/`barsDark` actions so the area behind the system bars follows Yammer's theme, not the phone's.
  - **Back key:** `useBackKey` in `lib/back.ts` keeps one history entry per level (an open Select, note or setup step, and each page above Home). The webview uses those up before the activity sees the key; with none left, `MainActivity.onBackPressed` backgrounds the app. Only add entries as a level opens from a tap, never after a Back: the webview's `goBack` skips an entry whose page added another without a tap, which drops Back out of the app.
  - The service must start with the app on screen: a foreground service started from the background can't use the microphone on Android 14+. It keeps access while it runs, so tapping Sushi works from any app. It doesn't survive a reboot; Home turns it back on the next time the app opens.
  - The process has to outlive the activity for Sushi to keep working, so `android::run` prevents Tauri's exit when the window goes and Back only backgrounds the app. Tauri can't build a second webview in one process, so reopening after a swipe from Recents restarts the process (`MainActivity.restartWhenIdle`).
  - API keys are in `secrets.bin` in the app's private storage (`allowBackup` off), AES-256-GCM encrypted with a random key that an Android Keystore key wraps (`Vault.kt`, prefs `vault`). `MainActivity` and `YammerService` call `Vault.unlock` before Tauri or the service reads a key, which hands it to Rust (`YammerNative.unlock`); without it, key reads fail as locked. An older plain `dev-secrets.json` is encrypted into it and deleted on first read. New installs keep 30 days of History and 10 recordings (`android::cloud_only`). Accessibility needs no events or other windows, and never pastes into a password field; the dictated clip is marked sensitive and cleared after a paste.
- **`apps/desktop/src`**: React 19, Vite and Tailwind 4, with hand-rolled primitives in `components/ui.tsx` (no Radix) using Sush's theme tokens. Icons are Phosphor (`@phosphor-icons/react`). Registry components from `@ui-shrushank`/`@ui-shrushank-pro` go in `components/ui/` (configured in `components.json`; the pro registry needs `SHRUSHANK_PRO_TOKEN`, which lives in the repo-root `.env`).
  - Both windows load `index.html`. `main.tsx` renders `overlay.tsx` when the window label is `overlay`, and the settings app otherwise.
  - `lib/tauri.ts` mirrors the Rust commands and serde types. **If you change a Rust command or serde type, update this file to match.**
  - `pages/onboarding.tsx` is the first-run setup guide (engine and API key, macOS permissions or the Wayland setup, hotkey, a first dictation). `App.tsx` shows it in place of the sidebar layout while `settings.onboarded` is false. Finishing or skipping sets the flag, and Help → "Run setup again" clears it. Nothing else sets it.
  - `lib/settings.tsx` holds the settings context. Every change saves through `settings_set`, which rejects a hotkey it can't register.
  - `lib/models.ts` is a module-level download store.
  - `lib/changelog.ts` bundles the repo-root `CHANGELOG.md` (`?raw`), or `CHANGELOG-android.md` on Android, for the "What's new" page (`pages/changelog.tsx`). The sidebar offers it once after an update, until `settings.seenChangelog` matches the installed version; a new install marks its own version seen during onboarding. An available update's notes come from the release body through the same parser.
  - `lib/presets.ts` holds the provider presets. Its `languages` list is repeated as `LANGUAGES` in `settings.rs` for the tray; keep the two in sync.
  - `lib/theme.ts` toggles `.dark` on `<html>` and keeps the native window theme in sync. Only the settings window applies the `theme` setting. The overlay always follows the OS.

## Gotchas

- Tauri API calls from the frontend beyond `core:default` (for example window dragging or `setTheme`) need a matching permission in `apps/desktop/src-tauri/capabilities/default.json`. That file covers both windows. Without the permission, the call fails at runtime.
- macOS Dock icon: `dock.rs` swaps it between `icons/macos-light.png` and `icons/macos-dark.png` to follow the system theme. The bundled `icon.icns` is static. On macOS 26, Finder, Launchpad and the pinned Dock icon follow the theme through `Assets.car`, compiled from `icons/AppIcon.icon` by `icons/build-mac-icon.sh`. That needs Xcode's `actool`, so `.github/workflows/mac-icon.yml` runs it on GitHub's macOS runners and commits `Assets.car` whenever the icon changes; never install Xcode for it. `tauri.macos.conf.json` bundles it; Tauri merges that file into every macOS build on its own, so no command needs a `--config` flag. Its `beforeBundleCommand` runs `icons/check-mac-icon.sh`, which stops the bundle when `Assets.car` wasn't compiled from the current `AppIcon.icon` (`Assets.car.stamp`, written by `build-mac-icon.sh`). So after an icon change, push, let the Mac icon workflow commit the new `Assets.car`, and pull before building a DMG. Regenerate every icon with `icons/source/make_icons.py`; never edit the outputs by hand. `Info.icon.plist` repeats `Info.plist`'s microphone string, so keep the two in sync. `build.rs` watches `icons/` so that a changed icon is re-embedded.

- macOS: Yammer has a Dock icon only while the main window is open (`dock::show` switches the activation policy between Regular and Accessory). With it closed, Yammer is an accessory app, which is what lets the overlay appear over other apps' full-screen Spaces. Clicking the Dock icon (`RunEvent::Reopen`) shows the hidden window. Yammer launches with no Dock tile at all: `LSUIElement` in both plists stops macOS adding one at exec, and `dock::start_hidden` (before `App::run`) stops tao making the app Regular as it finishes launching. Without both, the tile went on, off and on within a moment of launch, and the Dock kept a second Yammer "recent app" tile; keep both. `dock::dedupe_recents` still drops extra Yammer tiles that older builds left in `com.apple.dock` (at startup, restarting the Dock only when it finds one). `Info.plist` holds the microphone usage string. `Entitlements.plist` holds audio-input. Pasting needs Accessibility permission, checked with `AXIsProcessTrusted` in `platform.rs`. Transparency needs `macos-private-api`.
- App updates: `tauri-plugin-updater` reads `latest.json` from the latest GitHub release (`plugins.updater` in `tauri.conf.json`), and the sidebar's "Upgrade now" card (`lib/updater.ts`) downloads it, installs it and relaunches. Dev builds never check. `release.yml` signs the update bundles with the `TAURI_SIGNING_PRIVATE_KEY` secret, which lives in the `release` environment (main only) rather than the repo. Its actions are pinned to commit SHAs because they run with the key in reach; when bumping one, pin the new SHA and keep the version comment. The key was generated at `~/.tauri/yammer.key`, and losing it means shipped apps can never update again. Its public half is `plugins.updater.pubkey`. `bun run build` and `build:mac` add `tauri.local.conf.json`, which turns off `createUpdaterArtifacts` so local builds don't need the key. A release must bump `version` in `tauri.conf.json`, or the app sees nothing newer. Updates cover the Windows installers, the macOS `.app` (not the DMG) and the Linux AppImage; `.deb` installs don't self-update. Android checks too, differently: `android_update_check` reads GitHub's releases list for the newest `android-v*` release with an APK (`voice_core::releases::newer_android`), and on Android `lib/updater.ts` makes "Upgrade now" open that APK in the browser for Android's installer. The card is on the phone's Home. It only installs over a build signed with the same release key.
- Linux Wayland: `run()` forces `GDK_BACKEND=x11`, even over an inherited value (VS Code's terminal passes on `GDK_BACKEND=wayland`). Wayland has no keep-above, so a native Wayland overlay sinks behind other windows and shows up in the window list. Under XWayland the cursor position only updates while the pointer is over an X11 window. That's why the overlay's hit areas take the mouse on Linux and the overlay webview also listens to its own mouse events.
- Android is versioned and released on its own, separately from desktop. Its version is `version` in `apps/desktop/src-tauri/tauri.android.conf.json` (Tauri merges that file into Android builds only; it sets `versionName`, `versionCode` and what the app shows, since `platform::info` reads `app.package_info()`, not `CARGO_PKG_VERSION`), and its notes are `CHANGELOG-android.md`. The desktop version stays in `tauri.conf.json`, `Cargo.toml` and `package.json`. `release-android.yml` (Actions tab, or `gh workflow run release-android.yml`; it builds nothing else) builds a release APK signed by `signingConfigs` in `build.gradle.kts` (keystore from `YAMMER_KEYSTORE_*` env vars in CI, or an ignored `key.properties` locally) and publishes `Yammer_<version>_android.apk` as the `android-v<version>` release, created with `--latest=false` so it never becomes the updater's "latest" (an Android release has no `latest.json`). Anything that fetches the APK must look for the newest `android-v*` release, not `releases/latest`; the website's `/download/yammer?os=android` has to do the same. To release Android: add to `## Unreleased` in `CHANGELOG-android.md`, bump the version in `tauri.android.conf.json`, rename the heading, push to main, run the workflow and approve the `release` environment. The signing key is in the `release` environment secrets, with a backup in `~/.yammer`; losing it means installs can't update.
- Android: `gen/android` holds hand-written Kotlin and manifest entries, so it's committed; don't regenerate it with `tauri android init` without keeping them. If Gradle times out on Windows while curl can reach the same URL, set `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true`. Sideloaded apps must turn on "Allow restricted settings" in App info before Accessibility can be enabled, and Google Play requires a declaration for this use of the Accessibility API.
- On Windows, a normal app can't send keystrokes into elevated (admin) windows. There the paste silently does nothing, but the text is still in History.
