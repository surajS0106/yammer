# Build a macOS DMG

Builds an unsigned release DMG on this Mac. This is not a release: nothing is tagged or pushed (that's `/ship release`, which has `release.yml` build every platform).

## Project location

The Yammer repo lives at `~/Downloads/sush-pack/yammer` (`$HOME/Downloads/sush-pack/yammer`), next to its sibling projects in `~/Downloads/sush-pack/`. Every command and path below is relative to that folder; `cd` there first, whatever the current directory is.

## 1. Preconditions

- Running on macOS (`uname`). If not, stop and say so.
- The project folder exists (`test -d "$HOME/Downloads/sush-pack/yammer"`). If not, stop and say so.
- Mention uncommitted changes (`git -C "$HOME/Downloads/sush-pack/yammer" status --short`) if there are any. They are included in the build.

## 2. Build

Run from `~/Downloads/sush-pack/yammer`, in the background (the first release build compiles whisper.cpp with Metal and takes several minutes). Capture the real exit code; don't pipe the build into `tail`, which hides it.

```sh
cd "$HOME/Downloads/sush-pack/yammer"
bun install
bun run build:mac > "$TMPDIR/yammer-build.log" 2>&1
echo "EXIT $?"
tail -10 "$TMPDIR/yammer-build.log"
```

`build:mac` (root `package.json`) does the following:

- Puts `~/.cargo/bin` on PATH, since Rust may not be on the shell's PATH.
- `MACOSX_DEPLOYMENT_TARGET=11.0`, matching `bundle.macOS.minimumSystemVersion` in `tauri.conf.json`: whisper.cpp uses `std::filesystem` (macOS 10.15+), and Tauri's default target is 10.13, so the build can fail without it.
- `--bundles dmg` builds only the DMG (Tauri's `beforeBuildCommand` runs the tsc + Vite frontend build first).

Unlike Sush there's no sidecar or separate release config: `tauri.conf.json` is the whole bundle config, including `Entitlements.plist` (audio input) and `Info.plist` (the microphone usage string).

On macOS, Tauri merges `src-tauri/tauri.macos.conf.json` into every build on its own. It bundles the committed `icons/Assets.car` (the macOS 26 light/dark icon) and swaps in `Info.icon.plist` (`CFBundleIconName` plus the microphone string). Xcode is not needed: `Assets.car` is compiled by Xcode's `actool` on GitHub's macOS runners (`.github/workflows/mac-icon.yml`) and committed, with `Assets.car.stamp`, whenever `icons/AppIcon.icon` changes. Before bundling, `icons/check-mac-icon.sh` compares that stamp with the current `AppIcon.icon` and fails the build if they differ, so a DMG can't ship a stale icon. If the build stops there, the icon changed and CI hasn't recompiled it yet: tell the user to push (on `main` that starts the Mac icon workflow; otherwise `gh workflow run mac-icon.yml --ref <branch>`), wait for it, `git pull`, and build again. Don't bypass the check.

`AppIcon.icon/Assets/{light,dark}.png` are generated by `icons/source/make_icons.py`; don't edit them by hand.

## 3. If it fails

Quote the first real error from the log (`grep -n "error" "$TMPDIR/yammer-build.log" | head`).

- `'path' is unavailable: introduced in macOS 10.15` even with the env var set: a stale whisper CMake cache from a build without it. Run `cargo clean --release -p whisper-rs-sys` and build again.
- `cmake` or libclang missing: an environment problem (`brew install cmake`; libclang comes with the Xcode Command Line Tools), not a code failure.
- A `tsc` error: the frontend doesn't typecheck. Report it like `/typecheck` would; it isn't a packaging problem.

## 4. Report

Give the full DMG path (`~/Downloads/sush-pack/yammer/target/release/bundle/dmg/Yammer_<version>_<arch>.dmg`) and size, and note:

- It runs only on this Mac's architecture (aarch64 = Apple Silicon only).
- It is unsigned. On another Mac, open it with right-click → Open, or run `xattr -cr /Applications/Yammer.app` after copying it in.
- It requires macOS 11 or later.
- After installing, macOS asks for Microphone access on first dictation, and pasting needs Yammer enabled under System Settings → Privacy & Security → Accessibility. An unsigned rebuild counts as a new app, so a previously granted Accessibility entry may need removing and re-adding.
